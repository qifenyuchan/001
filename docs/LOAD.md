# 对 Agent 的压力：实测与边界

> 结论：**记忆服务是独立进程，不占模型的"脑力"；模型侧每轮只多花约 600 tokens 和两次工具往返。**
> 真正的固定成本是工具定义（默认 lite 3 个工具，约 1k tokens），不是记忆数据本身。

## 1. 压力分两种，不要混在一起

| 压力类型 | 落在谁身上 | 本项目情况 |
|---|---|---|
| CPU / 内存 / 磁盘 | 记忆服务进程（独立 Node 进程） | 1500 条记录时 heap ≈ 23MB；recall < 1ms；不占模型运行时 |
| 上下文 tokens / 工具调用 | 对话模型 | 轮首注入 ~400 tokens、轮末保存 ~180 tokens、工具定义 ~1k tokens（lite） |
| 延迟 | 模型等待 | 本地工具调用毫秒级；**没有外部模型 API**（旧版的外部抽取已删除） |

服务挂了不会阻塞对话：工具调用失败返回错误，聊天继续；UI 只是可选的观察面。

## 2. 实测数据（本机，2026-10-19）

### 2.1 工具定义（每次会话/每个请求的固定成本）

| 模式 | 工具数 | tools/list JSON | 估算 tokens |
|---|---|---|---|
| **lite（默认）** | 3（save / recall / search） | 3.1 KB | ~1.0k |
| full（`--tools full`） | 9（+ get/list/update/delete/restore/stats） | 5.5 KB | ~1.8k |

> 多数宿主会缓存 tools/list；不缓存时按每次请求计。**lite 比 full 每请求省约 0.8k tokens。**

### 2.2 每轮对话的增量

| 项 | 实测 | 说明 |
|---|---|---|
| 轮首 `memory_recall` 返回 | 374 字符 / 806 B ≈ **400 tokens** | 只含上一轮七字段，预算上限 1200 字符 |
| 轮末 `memory_save` 请求 | 355 B ≈ **180 tokens** | 只传七字段；正常轮**不传 raw_text** |
| 模型生成七字段 | 约 150–300 tokens 输出 | 与"写一句总结"相当 |
| **每轮合计** | **约 600–800 tokens** | 128k 上下文约占 **0.5%**；1M 上下文可忽略 |

### 2.3 规模与延迟

| 记录数 | 启动扫描 | recall | search | 进程内存 |
|---|---|---|---|---|
| 31（当前真实库） | 122 ms | 6.1 ms | — | ~10 MB |
| 500 | 495 ms | 0.85 ms | 3.7 ms | 10 MB |
| 1500 | 1.5 s | 0.70 ms | 8.8 ms | 23 MB |

- 写入约 **30 ms/条**（含 fsync 刷盘，保数据安全；相对模型响应时间可忽略）
- 启动扫描随文件数线性增长；10k 条预计数秒级，只发生在进程启动时
- recall 与 search 是内存操作，不受写入量影响（search 为 O(N) 线性打分）

> 本文只谈「对 Agent 的 token 与等待成本」。**服务本体的规模/并发承载**见
> [压力测试报告](STRESS-REPORT.md)（3000 条：写 32ms、search p95 58ms、冷启动 3s、8 并发 p50 401ms）。

## 3. 什么时候会真的吃力

1. **Agent 每轮都把 raw_text 塞进 memory_save** —— 等于把整轮对话再发一遍，token 翻倍。只在截断/缺字段时传。
2. **九工具全开 + 宿主不缓存 tools/list** —— 每请求多 ~0.8k tokens；用默认 lite。
3. **单会话几万轮** —— 启动扫描和搜索变慢；建议按项目拆 session，或后续加索引。
4. **小上下文模型（4k/8k）+ 多技能** —— 工具 schema 本身占比高；lite 模式 + 800 字符注入预算。
5. **把 UI 当常驻服务跑** —— 不影响对话，但多一个进程；不需要时 `--no-ui`。

## 4. 可调的减压开关

| 开关 | 默认 | 作用 |
|---|---|---|
| `tools_mode` / `--tools` | `lite` | 只暴露 3 个工具，省 ~0.8k tokens/请求 |
| `recall_max_chars` | 1200 | 注入块预算；可降到 600–800 |
| `range_every` | 10 | 调大（如 20）减少范围总结频率 |
| raw_text | 仅截断时 | 正常轮不传，避免整轮重复 |
| `--no-ui` | 否 | 不启动 UI 进程 |
| lite 下编辑/删除 | 走 UI/CLI | Agent 不需要的工具不进上下文 |

## 5. 和旧版对比

旧版每轮要：Stop 钩子抓会话 → ingest 服务 → 外部模型抽取（50s 超时）→ 插件归档 → 镜像库。
模型侧虽然不直接付费，但链路长、失败点多、时延不可控。
现在：**两次本地工具调用，无外部模型、无钩子、无端口依赖**。

## 6. 一句话心智模型

> 模型负责"说"和"记一行表"；记忆服务负责"存、合并、给你上一行"。
> 前者每轮多 ~600 tokens，后者在另一个进程里跑，毫秒级。
