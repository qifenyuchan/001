# 产品化 / 商业化路线（思考稿）

> 先纠正一个概念：**现在谈"商业化"不是去建公司、写 billing、做 SaaS。**
> 现阶段真正要解决的是——**陌生人能不能在 10 分钟内用起来，并且愿意留下来。**
> 收费是"有人反复用"之后的结果，不是起点。

## 二、这东西到底卖给谁

| 用户 | 真实痛点 | 愿意为什么付钱 | 规模判断 |
|---|---|---|---|
| **个人开发者**（Claude Code / Cursor / WorkBuddy 用户） | 多设备、多 Agent 记不住上下文；不想把记忆交给云 | 托管同步/备份、快照回滚（$3–8/月） | 最大，先做 |
| **小团队（3–20 人）** | 项目记忆只存在某个人脑子里；新人接手要重讲 | 团队空间、成员权限、审计（$3–8/人/月） | 有付费意愿，但要权限/合规 |
| **隐私敏感/企业** | 数据不能出内网 | 私有部署 + 支持合同（年费） | 客单价高，销售重 |
| **开源社区** | 想要可改、可导出的记忆层 | 不付钱，但带来采用与 PR | 传播基本盘 |

不建议一开始就做"给所有人用的云记忆"：那是 Mem0/Letta 的战场，拼的是资金和模型能力。

## 三、和现有产品的差异（必须讲清楚，否则没人用）

| 产品 | 形态 | 强项 | 我们的差异 |
|---|---|---|---|
| Mem0 | 云/OSS，向量抽取 | 生态大、接入快 | 我们不抽取成向量，不依赖外部模型；记忆是**七字段表**，可读可改 |
| Basic Memory | 本地 Markdown + MCP + 云同步 $15/月 | 本地优先、Obsidian 生态 | 我们**每轮结构化总结 + 只注入上一轮**，token 可控；有可编辑仓库 UI |
| Letta / MemGPT | Agent 运行时 | 自管理记忆 | 我们不绑定运行时，任何 MCP Agent 可用 |
| Supermemory / Zep | 云记忆 API | 检索/时序图 | 我们本地优先、零托管成本、数据在用户自己云盘 |

**一句话定位**：
> 给任何 MCP Agent 的「结构化、可审计、数据在你自己手里」的长期记忆层。
> 每轮一张七字段表，下一轮只带回上一张；多设备靠你自己的云盘同步，不经过我们的服务器。

## 四、免费 / 付费边界（open-core）

**永远免费（自托管）**
- 本地服务、MCP 工具、UI、文件同步（OneDrive/iCloud/Syncthing/git）
- 单用户无限记忆、完整导入导出（不锁格式）

**付费（托管增值，不卖记忆条数）**
1. **托管同步/备份**：端到端加密、跨设备自动同步、快照与时间点恢复
2. **团队空间**：成员、ACL、共享记忆、审计日志
3. **企业版**：SSO、私有部署支持、SLA、合规材料

原则：**核心能力不阉割；付费买的是"省事、协作、合规"，不是"记忆本身"。**

## 五、三阶段路线与门禁（没达到就不进下一阶段）

### Phase 0：开源可用（目标 1–2 周）
- npm 包（`npx northstar-memory`）、GitHub 仓库、LICENSE、CI
- 3 分钟 quickstart：一条命令 + 一段 MCP 配置 + 一句协议
- 4 个宿主示例：Claude Desktop / Cursor / WorkBuddy / ZCode
- demo 数据 + 截图/GIF；中英双语 README
- issue/PR 模板、CHANGELOG、版本策略

**门禁**：一个陌生人照 README 10 分钟内跑通；npm 包 <1MB；0 个 P0；安装失败有明确报错。

### Phase 1：社区验证（1–2 个月）
- 找 10–30 个真实用户（先中文 Agent 社区，再全球 MCP）
- 兼容性矩阵、真实使用案例、基准（token/延迟/召回）
- 每周固定时间处理 issue；建群/Discord
- 收集"最想要什么"：同步、团队、还是检索质量

**门禁**：≥10 个周活仓库、≥3 个外部 issue/PR、2 周留存 ≥30%。
达不到 → 继续打磨，不写收费代码。

### Phase 2：收费验证（有信号才做）
二选一，不要同时做：
- **A. 托管同步**：账号 + 加密对象存储 + 订阅（Stripe / 支付宝）
- **B. 团队空间**：成员/ACL/审计 + 按人订阅

**门禁**：≥20 个明确愿意付费的用户（预售/访谈/定金），否则不做。
首批定价参考：个人 $5–9/月；团队 $3–6/人/月；企业年费另谈。

### Phase 3：团队/企业
SSO、审计导出、私有部署镜像、支持合同。

## 八、三个必须拍板的决策

### 0. 已拍板（2026-10-19）
- **首发社区 = 中文 Agent 生态**（WorkBuddy / ZCode / Cherry Studio / Dify），README 出英文版
- **收费 = 暂不收费**，先做采用与留存；等 20 个愿付费信号再启动 Phase 2
- **License = MIT（已定，2026-10-19）**

### 1. License 速查与选择

| | MIT | Apache-2.0 | AGPL-3.0 |
|---|---|---|---|
| 类型 | 宽松 | 宽松 + 专利授权 | 强 copyleft |
| 闭源分发 | 可以 | 可以 | 不可以（衍生作品必须 AGPL） |
| 闭源 SaaS | 可以 | 可以 | 不可以（网络服务须提供源码） |
| 企业接受度 | 高 | 最高 | 低（很多公司禁用） |
| 传播速度 | 最快 | 快 | 较慢 |
| 保护托管收费 | 弱 | 弱 | 强 |
| 双许可 | 可（需 CLA） | 可（需 CLA） | 可（社区 AGPL + 商业授权） |

- 当前选择（暂不收费 + 中文社区首发）→ **MIT 或 Apache-2.0** 更利于采用
- 若未来确定卖托管同步 → **AGPL-3.0**（Basic Memory 同款）能阻止“直接抄去开闭源云”
- 没有 LICENSE 文件 = 默认保留所有权利，别人不能用；发布前必须定
- **建议**：MIT（简单、传播快）；企业市场明确后再评估 Apache-2.0 / 双许可

### 2. 首发社区（已定：中文 Agent 生态）
- 中文优先（WorkBuddy / ZCode / Cherry Studio / Dify）：竞争少、反馈快
- README 同时提供英文版，方便后续进全球 MCP 社区
- 首发 2 周内只在一个社区发声，避免摊薄

### 3. 第一个收费点（已定：暂不收费）
- 先在 Phase 1 收集“愿付费信号”（访谈/预售/定金）
- 达到 20 个信号后，优先做**托管同步/备份**；团队空间放 Phase 3
- 不卖记忆条数，核心永久免费，数据随时可导出

## 九、风险与底线

| 风险 | 应对 |
|---|---|
| 记忆含敏感信息 | 本地版不收集；托管版 E2E 加密 + 明确隐私政策；永不训练 |
| 竞品强大 | 不拼生态，拼"结构化 + 可编辑 + 数据自持 + 中文" |
| 支持成本吞掉个人时间 | 文档/模板/`sync doctor`/自动诊断；限定支持渠道与时段 |
| License 选错难回头 | 发布前定；已发布代码的许可不可撤销 |
| 平台依赖 MCP 生态 | stdio + HTTP 双通道；协议文档独立于宿主 |
| 收费太早伤采用 | 核心永久免费；收费只卖托管/协作/合规 |

## 十、如果只做一件事

**把"陌生人 10 分钟跑通"做到极致**：一条 `npx` 命令、一段可复制的 MCP 配置、一个能立刻看到效果的 demo。
在做到这件事之前，不做官网、不做支付、不做多租户。
