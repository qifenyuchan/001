# 北极星记忆 · Agent 使用约定（AGENTS.md）

> 把本文件（或 `SKILL.md` 压缩版）加入 Agent 的系统提示 / 技能库。协议只有五条。

## 五条硬约定

1. **轮首先取**：每个用户回合开始时，调用 `memory_recall`（`session_id` 用稳定会话标识），
   把返回的文本块**原样**放入上下文，不要复述、不要总结它。
2. **轮末必存**：每个回合结束时调用 `memory_save` 提交七字段表。
   **永不跳过**：被截断也要存（`truncated:true` + 已有字段 + `raw_text`）。
3. **只注入上一轮**：不要请求全量历史注入。几十轮之前的事用 `memory_search` 按需检索。
4. **范围总结**：`memory_save` 返回 `range_due:true` 时，系统已自动生成机械范围条；
   你可以再用 `kind:"range"` + `range_from/range_to` 提交一条更好的，覆盖它。
5. **隐私红线**：绝不保存 API key、密码、令牌、身份证号等敏感信息。

## session_id 怎么定

- 用宿主提供的稳定会话 id（如 `session_id`、聊天 id）。同一会话**始终用同一个值**。
- 没有稳定 id 时，用工作区名 + 日期，例如 `ws-northstar-20261019`。
- 服务端会清洗成 `[a-z0-9_-]`、最长 48 字符；`default` 是兜底桶，不建议长期使用。

## 七字段怎么写

| 字段 | 写什么 | 不写什么 |
|---|---|---|
| 时间 | 事件发生日期或时间（`2026-10-19` / `2026-10-19 22:03`） | "今天""刚才"（跨会话会失真） |
| 地点 | 环境/项目/文件区域；无关写 `无` | 空着 |
| 人物 | 用户、Agent、涉及的角色；无关写 `无` | 空着 |
| 事情 | **一句话说清这一轮做了什么**（最重要） | "讨论了问题""进行了交流"这类空话 |
| 原因 | 为什么要做（触发点/目标）；未知写 `无` | 长篇论证 |
| 结果 | 做成了什么 / 结论 / 产出（可验证） | "已完成"三个字 |
| 重点 | 下一轮最需要记住的一条（决策、约束、待办） | 重复"事情"原文 |

**示例（好）**

```json
{
  "时间": "2026-10-19",
  "地点": "北极星项目 / src/store",
  "人物": "用户、Agent",
  "事情": "修复 recission 冲突：编辑改为部分字段合并，避免空值覆盖整条记录",
  "原因": "整对象 spread 会把未传字段清空，导致质量从 partial 跌到 degraded",
  "结果": "48 个测试全绿；编辑只影响传入字段",
  "重点": "编辑接口必须用 partialFields 合并，禁止整对象覆盖"
}
```

**示例（坏）**

```json
{ "事情": "聊了聊", "结果": "完成了", "重点": "继续" }
```

## 截断与异常

- 回答被截断/超时：立即 `memory_save`，`truncated:true`，`raw_text` 放已产出的内容。
- 只有原文没有结构：只传 `raw_text`，服务会生成骨架并标记 `degraded`。
- 关键结论先落一条（checkpoint），回合结束时用**同一个 `turn_no`** 再存一次覆盖（天然键 upsert，不会重复）。
- `turn_no` 不传由服务端自动分配；补录历史时显式传。

## 什么时候检索

用户提到"之前/上次/几十轮前/那个方案"、需要历史决策依据、或要引用旧结论时：

```
memory_search(query="关键词", session_id="...", limit=5)
```

命中结果只有摘要；需要全文再 `memory_get(id)`。检索结果**不要**自动整段注入，按需引用即可。
